## ⚠️ 먼저 — 정말 전환해야 하나?

**1순위 대비책은 AI 전환이 아니라 "AI 없이 CLI 직접 실행"이다.**

한도에 걸리는 시점은 대개 후반(15시 전후)이고, 그때 필요한 건 새 코드가
아니라 **파라미터 조정**이다. 그건 AI 없이 된다:

```bash
# AWS 자격증명은 이 PC 의 ~/.aws/credentials 에 있다 (AI 소유가 아니다)
# 128코어 스윕은 Claude 없이 그대로 돌아간다
# 그대로 복사해서 쓸 수 있다 (인자 뜻은 아래 표)
python run_batch.py \
  --solver "./sol" \
  --inputs "inputs/*.txt" \
  --judge "./judge {input} {output}" \
  --params "SEED=1,2,3;MODE=a,b" \
  --jobs 128 --timeout 10 --out r.csv
```

→ **표에서 "승"이 많고 "bad"(무효)가 0 인 설정을 고르면 끝이다.**
전환은 "새 코드를 꼭 짜야 할 때"만 고려한다.

## 4. ★ 도구 사용법 — 여기가 제일 중요하다 (미리 채워둔 부분)

**이미 만들어져 있고 검증도 끝났다. 새로 만들지 마라.**
이 절은 당일에 채우는 게 아니라 **미리 완성해둔 것**이다. 그대로 쓰면 된다.

### 4-1. 연동 규약 2개 — 어기면 도구가 아예 안 붙는다

이건 추측으로 알 수 없는 부분이라 먼저 읽어라.

1. **솔버는 `stdin` 으로 입력받고 `stdout` 으로 답을 낸다.**
   입력 파일 경로를 인자로 받게 만들면 `run_batch.py` 에 못 붙는다.
2. **지표는 `stderr` 에 `key=value` 형식으로 찍는다.**
   ```
   cost=15406 iters=999932 t_wall=1.700
   err=overlap          # 실패 사유도 같은 형식으로
   ```
   `run_batch.py` 가 솔버 stderr 와 채점기 출력에서 이 토큰을 전부 긁어
   CSV 열로 만든다. 숫자와 `err*`/`reason` 문자열을 자동 수집한다.

### 4-2. `run_batch.py` — 병렬 스윕 (제일 많이 쓴다)

```bash
# 그대로 복사해서 쓸 수 있다 (인자 뜻은 아래 표)
python run_batch.py \
  --solver "./sol" \
  --inputs "inputs/*.txt" \
  --judge "./judge {input} {output}" \
  --params "SEED=1,2,3;MODE=a,b" \
  --jobs 128 --timeout 10 --out r.csv
```

| 인자 | 뜻 |
|---|---|
| `--solver` | stdin→stdout 규약을 지키는 실행 명령 |
| `--inputs` | 폴더 또는 glob |
| `--judge` | `{input}` `{output}` `{tmp}` 가 실제 경로로 치환된다 |
| `--params` | `"A=1,2;B=x,y"` → 곱집합. **환경변수로** 솔버에 전달된다 |
| `--jobs` | 병렬도. 기본값이 코어 수라 **건드릴 필요 없다** |

- **`--maximize`**: 점수가 **클수록 좋은 문제면 반드시 붙인다.**
  안 붙이면 제일 나쁜 설정을 1등으로 고른다 (조용히 틀린다)
- **시간을 재는 게 목적이면 `--jobs 1`** — 병렬이면 경합으로 부풀려진다
- 출력 표 읽는 법: `bad`(무효)가 0 인 것 중에서 **`승`이 많은 것**을 고른다.
  `평균`은 값이 큰 입력에 휘둘리니 참고만.
  **`최악비` 열도 반드시 본다** — 작은 승리 여러 번 + 큰 패배 한 번인
  설정이 `승`만으로는 1등처럼 보인다. 1.5배 넘으면 경고가 뜨고
  **어느 입력인지도 같이 찍힌다**

### 4-3. `gap.py` — 최선의 경우와 얼마나 벌어졌나

```bash
python gap.py --ours "처리=78,셋업=180" --bound "처리=72,셋업=30" --total-ours 258
#   → "격차의 96% 가 셋업에서 온다" 처럼 **무엇을 고쳐야 하는지** 알려준다
```
- 내 답과 하한을 **같은 항목으로 쪼개서** 넣어야 한다
- `--total-ours` 에 채점기 총점을 넣으면 쪼개기가 틀렸는지 먼저 걸러준다
- **"몇 배 차이"는 보지 마라.** 벌점 항이 크면 몇 건만 놓쳐도 폭발한다
