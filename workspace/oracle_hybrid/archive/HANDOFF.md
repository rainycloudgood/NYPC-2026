## 1. 문제 요약

(R+2)×C 격자. 0행 = 꽃 C개, R+1행 = 굴 C개, 가운데 R행이 설계 영역.
꽃 i는 씨앗 A_i개를 t = M−A_i+1 … M 동안 **초당 1개씩** (1,i)에 떨어뜨린다
(모든 생산 창이 t=M에 동시에 끝남 — 이 성질이 설계 전반의 핵심).
굴 i는 B_i개를 원한다. ΣA = ΣB, max(A)=M, max(B)≤M.

참가자는 R(C ≤ R ≤ C+20)과 R×C 배치도를 출력한다.

### 장치 규칙 (공식 예제 코드 sample_code.py로 확정)
- **다람쥐**: U/D/L/R 중 **서로 다른** 방향을 골라 나열 (예: `D`, `DR`, `UDLR`).
  - **같은 방향 중복 불가!** `DD`, `RRD` 등은 형식 위반(0점). 최대 4방향.
  - 매초, 마지막으로 보낸 방향의 **다음 순서부터** 커서가 돌며 1개씩 보냄.
    같은 방향으로는 초당 최대 1개 → 셀 처리량 = 방향 수(≤4)/초.
  - `X` = 방향 없음(씨앗이 오면 영구 정체).
- **햄스터**: 같은 행/열의 **거리 ≥ 2** 칸으로 초당 1개. 표기 `12D`, `3R` 등.
  - **굴로 직접 던질 수 있고, 중간 칸들을 완전히 건너뜀**(간섭 없음) — 배선의 핵심 도구.
- 꽃(0행)으로는 보낼 수 없음.

### 매초 진행 순서 (공식 시뮬레이터 기준)
1. **수확**: 씨앗이 (1,i)에 추가됨. **같은 초의 '보내기'에서 바로 보낼 수 있음**.
2. **보내기**: 모든 장치가 동시에 min(보유, 처리량)개 발송.
3. **과부하 판정 + 받기**: **보내기 후 씨앗이 1개라도 남은 칸은 과부하** —
   그 턴에 받은 씨앗을 전부 **보낸 칸으로 반송**. **굴도 과부하됨**(아래 4 이후
   잔량이 있으면). 반송받은 쪽은 다음 턴 재발송(커서는 이미 전진한 상태!).
4. **저장**: 굴에 씨앗이 있으면 **초당 1개만** 저장(B'에 집계). 저장된 건 회수 불가.

### 채점
- E = Σ|B'−B| (오차), L = ΣB − ΣB' (손실), D = L>0 ? T : (마지막 저장시각 − M)
- **Cost = 2^(R−C) + max(E, D) + T×L**
- 손실 1개 = T(=2,000,000) 페널티 → **L=0이 절대 조건**.
- 스텝업: 테스트별 기준비용 대비 점수 = 만점 × 0.9^(Cost/기준 − 1). 기준은 1~5 수준
  → **Cost가 한 자릿수여야 점수가 나옴**.
- 챌린지: 참가자 상대평가 (나보다 낮은 비용 비율로 감점).

### 두 가지 트랙
- **스텝업**: 공개 입력 15개 (`Downloads\input_1~15.txt`), 소규모 (T ≤ 2000, 총량 ≤ ~4000, C 2~8).
- **챌린지**: 대규모 (`Downloads\1.txt~5.txt` 확보, C 7~10, T=2,000,000, ΣA=1,000,000+α,
  M ≈ 26만~41만). 중간평가 30개 데이터는 C∈[5,10], M 구간별 생성(랜덤 조성 수열 2개 중
  최댓값 큰 쪽이 A). 제출 코드 실행 시 data.bin(≤10MiB) 런타임 참조 업로드 가능.
- 입력 형식: `C T M / A[0..C-1] / B[0..C-1]` (공백 구분).

## 2. 핵심 설계 원리 (검증 완료)

### 2.1 정확한 분할 (E=0의 수단)
k방향 다람쥐는 씨앗 1개당 커서가 1칸 전진하므로, **총 N개를 처리하면 토큰의
t번째 방향이 정확히 ceil/floor(N/k)개를 받는다 (앞쪽 N%k개 방향이 ceil)** —
도착 타이밍과 무관, N이 41만이어도 성립. 이를 재귀 적용한 **분할 트리**로
임의 수요 분배가 가능: 노드의 수요집합을 부분합 DP(안 되면 수요 하나를
쪼개서라도)로 그룹 합이 정확히 ceil/floor(N/k)이 되게 나눠 자식으로 재귀,
리프에서 굴로 배송 → **E=0 보장**. 2방향(`DR`형)과 3방향(`DLR`형, 깊이 급감) 사용.

### 2.2 반송(bounce) 안전성
- 반송이 **다중 방향 다람쥐(분배기)에 닿으면 개수가 오염**된다 (커서가 이미
  전진했는데 씨앗이 돌아와 다른 방향으로 재발송됨).
- **햄스터/단방향 다람쥐는 반송돼도 같은 곳에 재시도 → 개수 보존, D만 증가.**
- 따라서 배선(릴레이·횡이동·굴 직투)은 전부 단방향 장치로 하고, 분배기 하류에
  정체가 닿지 않게 여유율을 둔다.

### 2.3 굴 유입률 제약 (D≈0의 조건)
- 모든 생산 창이 M에 끝나므로 굴 유입률의 피크는 항상 M 직전.
- **한 굴로 모이는 조각(리프)들의 유입률 합 ≤ 1** (리프 유입률 = 2^-깊이 …
  분할 경로상 비율의 곱)이면 지속 반송이 없고 D ≈ 트리 깊이 + 배선 홉 수준.
- 위반하면 대규모에서 반송 누적으로 D가 수천~수만이 됨 (max(E,D)라 치명적).
- 수확 당일 발송 규칙 덕에 직송 경로는 D=0~2까지 가능.

### 2.4 수송 행렬 관점 (챌린지용 이론 골격, v4)
X[i][j] = 열 i → 굴 j 유량 비율(이진유리수)로 두면:
① 행합 = 1 (완전 분할), ② Σ_i X_ij·A_i = B_j (ceil/floor로 정확),
③ **열합 Σ_i X_ij ≤ 1** (= 2.3의 피크 제약).
수송문제 기저해는 비영 원소 ≤ 2C−1개 → 조각 ~19개로 배선이 격자 예산 안에 들어감.
③이 LP상 불가능한 데이터는 그 잔차만큼 D>0이 구조적 하한.

## 6. 함정 모음 (재발 방지)
- `DDDD` 같은 방향 중복 문자열 → 형식 위반 0점 (과거 오답의 원인).
- 반복문자 순환 패턴으로 비율 분배하는 설계는 **이 규칙에선 불가능** (방향당 1개/초).
- 과부하 판정은 "보내기 후 잔량 > 0" (용량 초과가 아님!). 굴도 과부하됨.
- 반송이 분배기에 닿으면 E가 예측 불가로 오염 — 시뮬의 bounces>0이면 의심.
- 수확한 씨앗은 같은 초에 발송 가능 (D 계산 시 홉 수 − 1).
- 햄스터 거리는 반드시 ≥ 2 (인접 칸은 다람쥐로).
- 입력 파일 ↔ 사이트 테스트 번호 매칭을 반드시 확인 (잘못 내면 오답).
