# 🚀 KICKOFF — 대회 세션 시작 시 Claude 가 읽는 유일한 문서

> 이 파일 하나로 충분하다. 다른 문서는 **필요할 때 사용자가 가리켜준다.**
> **다른 문서를 찾아 읽지 마라.** 필요한 건 다 여기 있고, 나머지는 `archive/` 에 있다.

## 1. 역할

**사용자 = 눈 + 손 + 제출 버튼. Claude = 엔진.**

Claude 는 대회 화면을 못 본다. 문제 읽기·규정 확인·실제 제출은 사용자만 할 수 있다.
핵심 루프: **Claude 가 답 생성 → 사용자가 제출 → 점수를 알려줌 → 다음 수.**
이 한 바퀴가 빠를수록 순위가 오른다.

## 2. 실격 방지 (절대)

- **AI 는 Claude 하나만.** 다른 에이전트 동시 사용 ❌
- **서브에이전트 호출 금지**: `/code-review` `/simplify` `/fork` `/batch` `/workflow`
  `ultracode` `ultraplan` — **프롬프트에 단어만 써도 켜질 수 있다**
- 동시 실행이 허용되는 건 **AI 가 아닌 프로그램**(채점기·스윕)뿐
- 제출 코드 ≤1MiB
- (대회 전) 외부 LLM 데이터학습 opt-out — 공식 규정상 **의무**. 설정→Privacy 에서 끈다

## 3. 사용량 한도 (Pro 구독)

5시간 롤링 한도가 대회 길이와 겹친다. 실측 5시간 = 76% 소모, **여유 24%.**

- ❌ **파일 통째 재작성 금지** → 부분 수정. (10k 출력 = 일반 턴의 5~7배)
- 단순 작업은 effort 낮추기 / 같은 파일 반복해서 읽히지 않기
- 한도에 걸려도 `run_batch.py`·빌드는 Claude 없이 돈다.
  **AWS 자격증명도 이 PC 의 `~/.aws/` 에 있다** — AI 소유가 아니라서
  128코어 스윕도 그대로 돌아간다.
  → 문제 파악 직후 **run_batch 명령어 한 줄을 메모장에 복사**해둘 것
- ★ **한도 90% 근처에 오면 사용자에게 먼저 알리고** `HANDOFF_CODEX.md` 의
  빈칸을 채울 것(5분). 다른 AI 로 넘길 때 그 파일 하나만 주면 된다.
  (예선에서 실제로 90% 에서 Codex 로 넘어간 전례가 있다 — 규정상 문제없다.
   단 **Claude 를 완전히 종료한 뒤** 넘어가야 한다)
  ※ 도구 사용법 절(§4)은 **이미 다 채워져 있다** — 그 부분은 쓸 필요 없다.
  ※ 그래도 **1순위는 AI 전환이 아니라 "AI 없이 CLI 직접 실행"** 이다.

## 4. 시간 관문 (11:00–16:00)

| 시각 | 할 일 | 넘어가기 전 조건 |
|---|---|---|
| 11:00 | 문제 원문 붙여넣기 + 규정 5가지 확인 | |
| **11:30** | **아무 답이나 1개 제출** | 0점 방지. 점수 0이어도 된다 |
| 11:30~12:00 | 정확한 채점기 만들기 + 기준 제출본 | 공식 점수와 값이 일치할 것 |
| 12:00 | 첫 중간평가 입력 수령 | 서버는 아직 안 띄움 |
| **12:30** | **길 확정 — 이후 안 바꾼다** | AWS 띄움 |
| 12:30~15:00 | 주력 + **계속 스윕**. 30~40분마다 제출 | 안정 코드 생기면 즉시 스윕, 중간평가 올 때마다 재확인 |
| 15:00~15:30 | 마지막 전체 확정 스윕 (`run_batch.py`) | 유일한 스윕 창이 아니라 마지막 확인 |
| **15:30** | **새 구조 시작 금지** | 손 놓는 게 아니다 — 파라미터·시드 스윕은 계속 |
| 15:30~15:50 | 안전한 개선만 | 되돌리기 10초짜리만. 나빠지면 즉시 롤백 |
| **15:50** | **코드 바꾼 마지막 제출** | 확인 마친 것만 |
| **16:00+1h** | **대표 답안 최종 확인** | 최종점수는 마지막 제출이 아니라 대표 답안. 종료 후도 바꿀 수 있다 |

**11:30 을 넘겼다면**: 목표를 "점수 나는 답"→"형식만 맞는 아무 답"으로 즉시 내린다.
12:00 넘으면 다른 일 전부 중단. 12:30 넘으면 문제 성질 파악을 미뤄서라도 제출 먼저.

**★ 가장 중요한 규율 — 시각이 아니라 상태다**
**항상 "검증 통과본"이 올라가 있게 유지한다.** 통과한 것을 `sol_good` 으로 따로
보관하고, 새로 낸 게 이상하면 **10초 만에 되돌린다**. 제출은 **10초에 1회** 가능하다.
이 규칙만 지키면 늦게까지 과감하게 시도해도 점수가 안 떨어진다.
→ 제출이 싸므로 **짐작하지 말고 내보고 반응을 본다.** 무효가 나도 오류 메시지가 정보다.

## 5. 규정 5가지 (사용자가 확인해서 알려줌)

1. **입력을 미리 주나?** → 예상 답 "아니오"(최종평가 입력은 무작위·비공개)
2. 제출 형식: **코드 1개? 답 파일?** → 코드면 **C++ 고정**
3. 실행 시간제한: 입력당 몇 초
4. 채점 방식 → **입력별 상대평가면 평균이 아니라 "몇 번 이겼는지"로 판단**
5. 최종 점수 = 마지막 제출? 최고점? → 모르면 마지막 제출로 가정

## 6. 준비된 도구 (경로: 이 폴더)

| 도구 | 당일 할 일 | 용도 |
|---|---|---|
| `skeleton.cpp` | 함수 3개 채우기 | 시간예산 루프·이중 클럭·env 오버라이드 |
| ↳ ⚠️ | 단계별 예산분할(생성/선별/정확)은 **평가가 비싼 문제 전제**다. 반대면 버리고 "생성→평가" 한 덩어리로 | |
| `terrain.py` | `load/dump/mutate` 3개 (~10줄) | SA 가 통하나 판정 **+ 어떤 변이를 쓸지** |
| ↳ ★ | **변이를 2~3가지 만들어 각각 돌리고 "더 좋아지는 비율"을 비교한다.** 실측 1.3% vs 11.3%(8.7배) | |
| `gap.py` | **없음** (숫자만 입력) | 하한과의 격차를 항별로 분해 |
| ↳ 전제 | **내 답과 하한을 같은 항으로 쪼개야** 쓴다. 못 쪼개면 아직 하한을 이해 못 한 것 | |
| `run_batch.py` | **없음** (명령줄만) | 전 입력 × 전 설정 병렬 스윕 |
| `aws/` | `allow-ip.sh`→**`launch.sh max`** | 12:30 띄움 → **15:50까지 계속**. 128코어 하나로 통일(갈아타지 않음). 끝나면 `teardown.sh` |

**연동 규약 2개** (어기면 도구가 안 붙는다)
- 솔버는 **stdin → stdout**
- 채점기·솔버는 stderr 에 **`key=value`** 형식으로 지표를 찍는다 (`cost=123 err=overlap`)

## 7. 제출 코드 요건

- **C++ 단일 스레드** (채점은 1코어, 스레드 CPU 시간 합산)
- **anytime** — 언제 끊겨도 그때까지의 최선을 출력. 시간을 끝까지 쓴다
- **공식 판정은 CPU time**(스레드 합산)이다. `max(wall, cpu)`는 그걸 흉내낸
  **우리 프로그램 내부의 보수적 중단 기준**일 뿐 — 공식 판정 방식이 아니다.
  예산 = 제한 × 0.85
- 튜닝 값은 **환경변수로 빼둘 것** → 재컴파일 없이 스윕 가능

## 8. 판단 규칙 — 리허설 3회에서 실제로 데인 것들

**① 표본이 적으면 결론이 뒤집힌다. 그리고 단조롭지 않다** ★★★
같은 설정의 승률이 **0/3 → 7/9 → 10/15 → 23/27** 로 움직인 적이 있다.
3개 결론이 27개 결론의 정반대였고, 15개("차이 없음")에서 멈췄다면 버렸을 것이다.
→ **한 번 안정돼 보여도 아니다. 중간평가마다 다시 본다.**
→ 적은 표본은 틀린 답만이 아니라 **틀린 이론**을 만든다.

**② 구조적 직관은 측정에 진다** (리허설에서 4번 넘게 틀렸고 전부 측정이 잡았다)
→ 가설은 **별도 변형으로 넣고 재본다.** 확신해도 바로 갈아끼우지 않는다.

**③ 정적 추정 폐기 → 정확 평가.** 후보를 여러 개 만들고 정확히 재서 고른다.
채점이 싸면 후보를 늘려도 **손해가 구조적으로 0**이다 (리허설 3회 모두 통했다).

**④ 격차는 배수가 아니라 항별로 본다** — `gap.py`.
벌점·고정비 항이 단위비용보다 크면 몇 건만 놓쳐도 배수가 폭발한다.
("14.8배 격차"의 정체가 미연결 3쌍이었던 적이 있다.)

**⑤ 하한은 도달 가능성을 의심한다.** 필요 자원 > 가용이면 그 하한은 거짓.
단 자원이 남아도 불가능할 수 있다 — **자원 여유는 신뢰 근거가 아니다.**

## 9. 자주 나는 사고

- `g++ --version` 성공 ≠ 컴파일 가능 → **실제 컴파일 1회로 확인**
- 낡은 실행파일로 검증 → 빌드 후 **파일 시각 확인**
- 병렬로 시간 재면 부풀려진다 → 시간 측정은 **`--jobs 1`**
- 최대화 문제인데 `--maximize` 안 붙임 → **정반대 설정을 최선으로 고른다**
- 윈도우 CP949 출력 크래시 → `export PYTHONIOENCODING=utf-8`
