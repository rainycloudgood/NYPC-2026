# 씨앗 운반 — 배치도 생성기 (NYPC 챌린지)

## 파일
- `solution.py` — **제출용** (v3.1, 공식 규칙 준수, R=C+1)
- `validate.py` — 검증기+시뮬레이터 (공식 sample_code.py의 simulate()와 랜덤 31케이스 완전 일치 확인)
- `sample_input.txt` — 예시 입력 (`C T M / A[] / B[]`)
- `solution.cpp`, `checker.cpp` — 구버전 (폐기: 반복 방향 문자열은 형식 위반, 시뮬 의미론도 부정확)

공식 예제 코드: `C:\Users\<user>\Downloads\sample_code.py`, 실전 입력: `Downloads\1.txt`~`5.txt`
(실전 규모: C 7~10, T=2,000,000, M≈26만~41만, ΣA=ΣB=1,000,000+α)

## 공식 규칙 핵심 (예제 코드로 확인)
- **다람쥐**: U/D/L/R 중 서로 다른 방향을 골라 나열 (중복 불가 → 최대 4개, 초당 방향당 1개).
  `DD`, `RRD` 같은 반복 문자열은 **형식 위반**.
- **햄스터**: 같은 행/열 거리 ≥2 칸으로 초당 1개. **굴로 직접 던질 수 있고 중간 칸을 건너뜀**.
- **과부하**: 보내기 후 씨앗이 1개라도 남으면 그 턴에 받은 씨앗을 전부 반송.
  굴도 초당 1개만 저장 (초과 유입 시 과부하 → 반송).

## v3 전략: 열 스트림 통째 배정 + 햄스터 릴레이 직송
- 꽃의 생산이 초당 1개이므로 스트림을 자르지 않으면 모든 경로가 초당 ≤1개
  → 과부하가 원천적으로 없음 → **L=0 보장, D≈2**.
- σ = 열→굴 배정을 비트마스크 DP로 최적화 (Σ|A_i − B_σ(i)| 최소).
- 경로: `(1,i)` ↓(다람쥐/햄스터) → 전용 행(2..R) 스테이징 → 횡 이동 → ↓ 굴 직송.
  거리 1 구간은 다람쥐 `D`, 그 외는 햄스터 → **R = C+1로 충분, 2^(R−C) = 2**.
- **cost = 2 + max(E, 2)**. 실측(공식 의미론, 테스트 1~5): 전부 유효·L=0·D=2·반송 0,
  **E = 285k / 360k / 146k / 271k / 349k**.

## 점수 현실 (중요)
점수 = Score′ × 0.9^(Cost/Cost′−1), 기준비용 Cost′는 1~5.
- cost ≈ 10 → 약 80%, cost ≈ 30 → 약 40%, cost ≥ 300 → 사실상 0점.
- 즉 v3.1은 "정답" 판정은 받지만 대규모 테스트 점수는 0에 수렴.
- **E를 두 자릿수 이하로 만들어야 처음으로 의미 있는 점수가 나온다.**
  하프 스플릿 1~2단계(E를 절반~1/4로)로는 여전히 수만 단위 → 점수 0 그대로라 무의미.

## 개선 로드맵
1. **이분할 조각 은행**: 각 열 스트림을 `DR`형 다람쥐 연쇄로 재귀 이분할해
   크기가 정확히 계산되는 조각들(⌈N/2⌉, ⌈N/4⌉, …)을 만들고, 조각별로 굴에
   배정(부분합 그리디)해 B를 자릿수 단위로 맞춤 → E ≈ 0 목표.
   조각 수 ≈ C·log₂A ≈ 100+ → 칸 예산(≈(C+3)×C, 2^(R−C) 기준비용)에 맞춘
   배치·배선 기하가 핵심 난제.
2. 합류 안전성: 굴 합류는 송신자가 햄스터/단방향이면 반송-재시도가 개수 보존(D만 증가).
   다람쥐 분배기로의 반송은 개수 오염 → 분배기 하류에 정체가 닿지 않게 설계.
3. 입력 파일이 공개되므로(1~5.txt 확인) 테스트별 오프라인 최적화 후 답을 코드에
   내장하는 방식 검토 — 나머지 테스트 입력(15개 중 10개) 확보 + 채점 방식 확인 필요.

## 제출 방식 (2026-07-11 확인)
스텝업은 **출력 파일 제출(output-only)**: 사이트에서 입력 파일들을 내려받아
각 입력에 대한 출력 텍스트를 제출한다. 코드를 제출하는 게 아님 — 그동안의
'오답'은 제출물 종류가 어긋났을 가능성이 큼.
- `Downloads\input_1.txt` (3 200 100, A=B) → `outputs/output_1.txt`, Cost=1(기준비용) 달성.
- `Downloads\1.txt~5.txt` (대형) → `outputs/output_big*.txt`. 어떤 파일이 사이트의
  몇 번 테스트인지 반드시 대조 후 제출할 것 (잘못 매칭하면 오답).
- 출력이 파일 단위이므로 **테스트별 오프라인 최적화에 시간 제한이 없다** —
  탐색/조각 은행을 로컬에서 몇 분씩 돌려도 됨.

## 사용
```
python solution.py < input.txt > output.txt
python validate.py input.txt output.txt   # 유효성 + 공식 의미론 시뮬 + Cost
```
